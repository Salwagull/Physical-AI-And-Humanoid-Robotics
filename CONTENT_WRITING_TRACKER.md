## Quality Gate Checklist (Per Chapter)

Before marking a chapter complete, verify:

### Content Quality
- [ ] All sections written (Introduction through Exercises)
- [ ] Word count: 800-1500 words (excluding code)
- [ ] Flesch readability score: 8-10 (verified with tool)
- [ ] No jargon without glossary reference
- [ ] All claims backed by theory or examples
- [ ] Plagiarism check: < 5% (verified with tool)

### Technical Accuracy
- [ ] All code examples run without errors
- [ ] Code tested on: Ubuntu 22.04 + Windows WSL2
- [ ] Code follows conventions (PEP 8 for Python, etc.)
- [ ] Dependencies documented and available
- [ ] Output matches documentation
- [ ] No breaking API changes

### Visual Quality
- [ ] All diagrams present (minimum 1 per chapter)
- [ ] Diagrams are clear and properly labeled
- [ ] Diagrams use consistent style/colors
- [ ] ASCII diagrams replaced with proper graphics (if applicable)
- [ ] No broken image links

### Consistency & Navigation
- [ ] Chapter numbering and titles match sidebar
- [ ] All cross-references (→ to other chapters) exist
- [ ] Glossary terms linked and defined
- [ ] Learning objectives match content
- [ ] Summary references next chapter correctly
- [ ] No dead links to missing files

### Spec Compliance
- [ ] Aligns with Constitution principles
- [ ] Meets success criteria (SC-001 through SC-010)
- [ ] Constitutional compliance verified:
  - Beginner-first accessibility ✅
  - Spec-driven technical accuracy ✅

## Chapter Writing Workflow

### For Each Chapter:

1. **Research Phase** (2-3 days)
   - [ ] Gather references and documentation
   - [ ] Create outline
   - [ ] Plan code examples
   - [ ] Sketch diagrams

2. **Writing Phase** (3-5 days)
   - [ ] Write sections sequentially
   - [ ] Implement code examples (test on Ubuntu 22.04)
   - [ ] Create diagrams
   - [ ] Add exercises

3. **Review Phase** (1-2 days)
   - [ ] Self-review for clarity
   - [ ] Flesch score check (target 8-10)
   - [ ] Technical accuracy verification
   - [ ] Plagiarism check (< 5%)
   - [ ] Glossary term verification

4. **Validation Phase** (1 day)
   - [ ] Run all code examples
   - [ ] Verify all links
   - [ ] Check cross-references
   - [ ] Spec compliance check
   - [ ] Constitution alignment check

5. **Git Commit**
   - Message: `Chapter N: [Title] - [Brief description]`
   - Example: `Chapter 1: Physical AI Foundations - Complete with theory, code, exercises`
